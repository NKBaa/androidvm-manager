# 摄像头

模拟器摄像头有四种来源，可在「硬件」页为**后置**与**前置**分别配置。

## 可用模式

| 模式 | 说明 | 实测状态 |
|---|---|---|
| 无 | 关闭该摄像头 | ✅ |
| 模拟画面 | 模拟器自带的软件合成图案（彩条 + 网格） | ✅ 正常出画面 |
| 虚拟场景 | 3D 房间场景，可用鼠标在模拟器窗口里转动视角 | ⚠️ 后台模式会回退 |
| 宿主机摄像头 | 调用电脑上的真实摄像头（UVC / 内置摄像头） | ✅ 标准能力 |

切换后需要**重启虚拟机**才生效——模式写在 AVD 的 `config.ini` 里，
模拟器只在启动时读一次。

## 宿主机摄像头

点开后置/前置下拉框，在「宿主机摄像头」分组里选具体设备，
例如 `USB2.0 HD UVC WebCam`。程序通过两种方式枚举：

1. `emulator -webcam-list`（官方方式，能拿到准确的 `webcamN` 索引）
2. WMI `Win32_PnPEntity`（兜底，PNPClass 为 `Camera` / `Image` 的设备）

拿到后写成 `hw.camera.back=webcam0` 这类配置。

> 如果下拉框显示「未检测到摄像头」，说明当前进程没有设备访问权限
> （远程会话、服务账户、隐私设置里禁用了相机都可能）。
> 到 Windows 设置 → 隐私和安全性 → 相机，确认允许桌面应用访问相机。

## 屏幕区域（实验性）

「框选屏幕区域」的流程：

1. 用 Electron `desktopCapturer` 抓一张整屏截图
2. 弹出全屏遮罩，按住鼠标拖出要用的矩形
3. 用 `nativeImage.crop()` 裁剪并保存到 `_data/camera/`
4. 写 `hw.camera.back=imagefile:<路径>`

> ⚠️ **实测限制**：Android Emulator 37.3.5.0 上 `imagefile:` 模式会**静默回退成模拟画面**。
> 绝对路径、相对 AVD 路径、命令行参数 `-camera-back imagefile:...` 三种方式都试过，
> 均无效果且日志里没有任何报错。所以这个模式标为实验性——素材生成、预览、管理都能用，
> 但实际画面可能不生效。
>
> 想要真正实时跟随屏幕区域，需要一个 **Windows 虚拟摄像头设备**
> （DirectShow 源滤镜 / OBS Virtual Camera 这类），再让模拟器用 `webcamN` 指向它。
> 这需要安装驱动，不在本程序范围内。

## 为什么虚拟场景会回退

应用默认以 `-no-window` 后台方式启动模拟器（画面通过 `adb screencap` 拉到界面里显示）。
虚拟场景需要 GPU 实时渲染 3D 场景，无窗口模式下会退化为软件合成图案。

如果以可见窗口方式启动（配置里关闭「后台运行」），虚拟场景可以正常工作，
此时还能用模拟器控制台的 `virtualscene-image wall <图片>` 命令在运行时替换场景贴图。

## 实现位置

| 文件 | 作用 |
|---|---|
| `app/src/camera.js` | 枚举摄像头、写 config.ini、抓屏裁剪、素材管理 |
| `app/main.js` | `camera:*` IPC 处理器 |
| `app/renderer/renderer.js` | 下拉框填充、框选交互、素材列表 |
| `app/renderer/styles.css` | `.cam-imgs` / `.region-modal` 等样式 |

素材存放在 `<数据根>/_data/camera/`，删掉即可清空。
