# 虚拟摄像头

## 为什么要它

Android 模拟器的摄像头只支持四种来源：

| 模式 | 实测结果 |
|---|---|
| `emulated` | ✅ 可用（合成图案） |
| `virtualscene` | ❌ 无窗口/无桌面时回退成 `emulated` |
| `imagefile:<路径>` | ❌ 静默回退成 `emulated`（三种路径写法都试过） |
| `webcamN` | ✅ 透传宿主机 DirectShow 摄像头 |

前三种都指望不上，**唯一可靠的路径是 `webcamN`** —— 也就是把宿主机上的
DirectShow 视频设备原样透传给 Android。

MuMu、BlueStacks 也是这么做的：它们**不自带摄像头驱动**，用户装一个
OBS Virtual Camera / SplitCam 之类的第三方虚拟摄像头，模拟器里就能选到。
（参考 [MuMu + OBS 教程](https://www.youtube.com/watch?v=xmGqRAqYl5g)、[蓝叠 + OBS-Camera](https://blog.csdn.net/qq_45933228/article/details/132161618)）

所以本程序也走同一条路：**自带一个轻量的 DirectShow 虚拟摄像头**。

## 组成

| 文件 | 说明 |
|---|---|
| `softcam.dll` | DirectShow 视频输入滤镜，注册后系统里出现名为 `DirectShow Softcam` 的摄像头 |
| `vcam_feeder.exe` | 喂帧工具，读 BGR24 原始帧并调用 `scSendFrame` 推给滤镜 |

两者都随安装包附带（`resources\vcam\`）。

### 安装位置

```
C:\ProgramData\AndroidVM\vcam\
├── softcam.dll
├── vcam_feeder.exe
└── LICENSE-softcam.txt
```

用 `%ProgramData%` 而不是用户目录，是因为**机器级 COM 注册绝不能指向用户可写目录**，
否则同一用户下的其它进程可以替换 DLL，其它应用加载时就会被劫持。

## 工作流程

```
桌面屏幕区域
   │  Electron desktopCapturer + crop
   ▼
BGR24 原始帧  ──原子写入──▶  <数据根>\_data\vcam\frame.bgr
                                      │
                                      ▼
                              vcam_feeder.exe（10 fps）
                                      │ scSendFrame()
                                      ▼
                              softcam.dll（DirectShow 滤镜）
                                      │
                                      ▼
                    Android 模拟器 -camera-back webcamN
                                      │
                                      ▼
                               Android 里的相机应用
```

帧文件用「先写 `.tmp` 再原子改名」的方式更新，避免喂帧进程读到半截数据。

## 使用

1. 「硬件 → 摄像头 → 虚拟摄像头」点 **安装虚拟摄像头**（需要管理员权限）
2. 重启虚拟机
3. 点 **实时跟随屏幕区域**，框选要跟随的区域
4. 程序会自动把后置摄像头切到 `DirectShow Softcam`

## 卸载

卸载本程序时会自动：

1. `taskkill` 掉喂帧进程（否则 DLL 被占用）
2. `regsvr32 /u` 注销滤镜
3. 删除 `C:\ProgramData\AndroidVM\vcam\`
4. 清理 `HKLM\Software\AndroidVM\VirtualCamera`

也可以在界面里点「卸载」单独移除。

## 已知限制

- **需要管理员权限**：COM 注册写 HKLM
- **需要重启虚拟机**：摄像头模式在启动时读取，改了要重启才生效
- 装完可能需要重启系统，DirectShow 才会重新枚举设备
- 同时只能有一个喂帧进程（Softcam 的设计），多开实例共用同一个虚拟摄像头
