# 无线模拟：WiFi / 蓝牙 / 移动网络 / 电话号码

> 全部结论都来自本机实测（`google_apis` 镜像 + Android 14 + 模拟器 37.3.5.0）。
> 代码位置：`app/src/wifi.js`、`app/src/bluetooth.js`、`app/src/cellular.js`、`app/src/phone.js`

## 二、WiFi：实测细节

### 2.1 环境事实

```
wlan0   UP, MAC 02:15:b2:00:00:00
hwsim0  虚拟射频（mac80211_hwsim）
内置虚拟 AP: AndroidWifi（open 加密）
```

模拟器自带一个虚拟 AP，SSID 固定为 **`AndroidWifi`**，WiFi 开启后系统会自动关联，
supplicant 状态变为 `COMPLETED`，可读到完整链路信息：

```
SSID: "AndroidWifi", BSSID: 00:13:10:85:fe:01, MAC: 02:15:b2:00:00:00
RSSI: -50, Link speed: 2Mbps, Frequency: 2447MHz, Supplicant state: COMPLETED
```

### 2.2 关键坑位

| 做法 | 结果 |
|---|---|
| `cmd wifi set-wifi-enabled enabled/disabled` | ✅ 可用 |
| `cmd wifi status` | ✅ 可用（偶发返回空，需重试） |
| `cmd wifi list-networks` | ✅ 可读 |
| **`cmd wifi connect-network ...`** | ❌ **打崩 wifi 服务**：调用后立刻 `Can't find service: wifi` 或 `Broken pipe (32)`，已建立连接断开 |
| **`cmd wifi add-network ...`** | ❌ 同上，打崩服务 |
| **`cmd wifi forget-network`** | ❌ 同上 |
| 以 shell(uid 2000) 执行上述写命令 | ❌ `SecurityException: Uid 2000 does not have access`，必须 root |
| 关闭再开启 WiFi（toggle） | ✅ **稳定自动连上 AndroidWifi**（推荐） |

**结论**：WiFi 的"写配置"类命令在这个镜像上会触发 wifi 服务崩溃，
所以本工具**只用 toggle 方式连接**，并把 add/forget 加了护栏（默认拦截）。

### 2.3 为什么自定义 SSID 连不上

模拟器只有 `AndroidWifi` 一个真实 AP（由 virtio-wifi 提供）。
即使能保存自定义 SSID，也没有对应 AP 可以关联，supplicant 会一直停在
`DISCONNECTED`。扫描结果同样为空（没有其它 AP 广播）。

### 2.4 ⚠️ 能关联但拿不到 IP（重要）

实测：WiFi 关联成功后 supplicant 为 `COMPLETED`，能读到 SSID / BSSID / MAC / RSSI，
但 **`wlan0` 始终没有 IP**，系统界面停在 `Obtaining IP address…`：

```
$ ip -4 addr show wlan0
（空）
$ ip route
10.0.0.0/8 dev eth0 proto kernel scope link src 10.0.2.15    ← 实际联网走 eth0
```

原因与蓝牙同一个：**WiFi 的数据面（DHCP/slirp）依赖 netsim，而 netsimd 在本机起不来**。
所以：

- **L2 层**（关联、SSID、RSSI、BSSID）→ ✅ 应用读得到，像真的连了 WiFi
- **L3 层**（IP、真实上网）→ ❌ 拿不到地址；实际流量走 `eth0`（10.0.2.15）

对"骗过应用检测"来说 L2 信息通常够用；但如果应用要求 WiFi 必须是**活动网络**
（`ConnectivityManager` 报告 WIFI 为默认网络），这一层做不到。

## 三、蓝牙：为什么彻底不可用

### 3.1 根因链

```
模拟器蓝牙 → 需要 netsimd（虚拟 HCI 后端）
  ↓
netsimd.exe 启动失败: "Netsim daemon failed to start: 拒绝访问。(os error 5)"
  ↓
蓝牙协议栈拿不到 HCI 通道
  ↓
libbluetooth_jni.so → StackManager::StartUp 断言失败 → abort
  ↓
com.google.android.bluetooth 反复崩溃（"Bluetooth keeps stopping"）
  ↓
严重时拖垮 system_server（实测导致 wifi/package 服务消失、模拟器进程退出）
```

崩溃栈实测：

```
#03 liblog.so (__android_log_assert+306)
#04 libbluetooth_jni.so (bluetooth::StackManager::StartUp(ModuleList*, os::Thread*)+740)
#05 libbluetooth_jni.so (bluetooth::shim::Stack::Start)
```

### 3.2 netsimd 排查记录

| 检查项 | 结果 |
|---|---|
| `netsimd.exe --version` | ✅ `Netsim version: 1.0.27` |
| 默认 TEMP 启动 | ❌ `Failed to create temporary netsimd directory: Os { code: 5, PermissionDenied }` |
| 换 TEMP 到项目目录 | ⚠️ 临时目录问题解决，但仍在 `Netsim daemon failed to start: 拒绝访问` 处退出 |
| 指定端口启动 | ❌ 同样失败 |
| 命名管道 / TCP 监听能力 | ✅ 都正常（不是系统限制） |
| 是否有 rootcanal 替代 | ❌ 该版本只带 netsimd |

### 3.3 因此本工具的做法

- `bt.setEnabled(true)` **默认拦截**，返回明确原因，必须 `force: true` 才尝试
- `bt.setName()` 会把名称写进 `settings put secure bluetooth_name`（部分应用会读）
- `bt.getStatus()` 如实报告适配器状态（`OFF` / `backendReady: false`）

**诚实的结论**：这台机器上蓝牙无法真正开启，应用调用
`BluetoothAdapter.isEnabled()` 会得到 `false`。这不是配置问题，是模拟器
蓝牙后端（netsimd）在本机无法启动。

## 四、移动网络：实测细节

底层走模拟器控制台（telnet 5554）的 `gsm` 子命令，**真实生效**：

```bash
gsm signal-profile <0-4>              # 信号格数
gsm signal <rssi 0-31|none> <ber>     # 直接设 RSSI/BER
gsm data  <unregistered|home|roaming|searching|denied|off|on>
gsm voice <同上>
gsm meter <unmetered|none|low|high>
```

实测反馈（全部返回 `OK`）：

| 操作 | 结果 |
|---|---|
| 信号设为 4 级 | `gsm.signal.level=4`，rssi 映射 28 |
| 数据连接 home | 状态栏恢复数据图标 |
| 语音注册 home | 可正常接打电话 |
| 制式设为 5G | `persist.radio.rat.override=NR` |
| 漫游开关 | `gsm data roaming` + `settings put global data_roaming` |
| 运营商设为「中国移动」 | siminfo 的 `display_name` / `carrier_name` 生效 |

### 4.1 运营商为什么以 siminfo 为准

`gsm.operator.alpha` 这个属性会被 RIL 周期性覆盖回真实运营商（实测设完
立刻读回来还是 `T-Mobile`）。而 `siminfo` 表的 `display_name` 不会被覆盖，
应用读订阅信息时也是读它。所以：

- 写入：**两处都写**（siminfo + 属性）
- 读取：**以 siminfo 为准**，属性仅作参考（`operatorProp` 字段）

### 4.2 ⚠️ 运营商显示的两个层面

| 读取方式 | 返回 | 能否改 |
|---|---|---|
| `SubscriptionManager` / siminfo `display_name` | 你设的值（如「中国移动」） | ✅ 可改 |
| `TelephonyManager.getNetworkOperatorName()` / 设置界面显示的运营商 | RIL 上报值（`T-Mobile`） | ❌ 控制台无对应命令 |

实测截图里设置界面顶部仍显示 `T-Mobile`，这是 RIL 层上报的，
模拟器控制台的 `gsm` 子命令没有设置运营商名称的接口。
需要应用侧读到自定义运营商时，走 siminfo 这条路是有效的。

## 五、电话号码：实测细节

数据在 `/data/user_de/0/com.android.providers.telephony/databases/telephony.db` 的
`siminfo` 表。本机实测有 **2 条订阅记录**：

```
_id=1  number=+15555210001  display_name=T-Mobile  icc_id=8944500000000000001
_id=2  number=+15551234567  display_name=T-Mobile  icc_id=89860318640220133897
```

写入方式：直接 UPDATE siminfo（root + sqlite3），然后重启 `com.android.phone`
让订阅信息重载。支持同时改号码 / 运营商名 / ICCID。

短信注入走 `mmssms.db` 的 `sms` 表 + `threads` 表，中文内容经 base64 传输避免转义问题。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `cmd wifi status` 返回空 | wifi 服务正在重启 | 模块内置 3 次重试；仍失败则等几秒 |
| `Can't find service: wifi` | 之前调用过 connect/add-network 把服务打崩 | 等 5~10 秒自动恢复；重连用 toggle |
| WiFi 连上又断开 | 同上，服务崩溃导致 | 重新执行连接 |
| 蓝牙开关后系统卡顿/服务消失 | 蓝牙协议栈 abort 崩溃循环 | **不要开启蓝牙**；已崩溃则 `settings put global bluetooth_on 0` + 重启 |
| WiFi/蓝牙/电话全部异常 | userdata 累积损坏 | 抹掉 `userdata-qemu.img.qcow2` 等 qcow2 后冷启动（会丢失伪装，需重新应用档案） |
